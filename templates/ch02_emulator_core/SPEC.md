# SPEC — The LAB-8 Fictional CPU

LAB-8 is a tiny fictional 8-bit computer used throughout Chapter 2. It is
small enough to hold in your head, but its shape (registers, RAM, PC, flags,
fetch/decode/execute) is the same shape as every real core you will emulate
later: 8080, LR35902, ARM7TDMI.

## Machine state

```cpp
struct Cpu {
    uint8_t r[4];      // general registers r0..r3
    uint8_t ram[256];  // unified RAM; program loads at address 0x00
    uint8_t pc;        // program counter (8-bit, wraps mod 256)
    bool zero;         // Z flag
    bool carry;        // C flag (carry for ADD, borrow for SUB)
    bool halted;       // set by HALT or a step error; stops run()
};
```

- **Memory** is one flat 256-byte space. There is no I/O space. A program is
  copied to `ram[0x00..]` and `pc` starts at `0x00`.
- **PC wrap**: all address arithmetic wraps mod 256. An instruction whose
  operand bytes run past `0xFF` continues reading at `0x00`. This is defined
  behavior, not an error — real CPUs wrap too.
- **Flags** are ordinary booleans, updated only by ADD and SUB (see table).
  LOAD/STORE/LOADM/JMP/JZ never touch them.

## Instruction encoding

Instructions are variable length: one opcode byte followed by inline operand
bytes, stored big-endian in program order.

| Opcode | Mnemonic | Encoding      | Len | Cycles | Semantics |
|-------:|----------|---------------|:---:|:------:|-----------|
| `0x00` | HALT     | `00`          |  1  |   4    | `halted ← 1`. Pipeline drains: this instruction still costs 4 cycles. |
| `0x10` | LOAD     | `10 rr ii`    |  3  |   4    | `r[rr] ← ii`. Flags unchanged. |
| `0x20` | STORE    | `20 rr aa`    |  3  |   6    | `ram[aa] ← r[rr]`. |
| `0x30` | LOADM    | `30 rr aa`    |  3  |   6    | `r[rr] ← ram[aa]`. |
| `0x40` | ADD      | `40 aa bb`    |  3  |   4    | `r[aa] ← r[aa] + r[bb]` (mod 256). `Z ← truncated result==0`, `C ← carry out (wide sum > 0xFF)` |
| `0x50` | SUB      | `50 aa bb`    |  3  |   4    | `r[aa] ← r[aa] - r[bb]` (mod 256). `Z ← result==0`, `C ← borrow (r[aa] < r[bb] as unsigned)` |
| `0x60` | JMP      | `60 aa`       |  2  |   3    | `pc ← aa`. Absolute jump; the target replaces the pc outright (no +1 afterwards). |
| `0x70` | JZ       | `70 aa`       |  2  | 3 taken / 2 not taken | if `Z`: `pc ← aa`, else fall through. |

The first operand byte of ADD/SUB names the *destination* register; the second
names the source. Both are register indices that must be exactly `0..3`.
A register byte outside `0..3` is a reserved encoding, not a modulo: real ISAs
trap or UNDEF on reserved encodings, and so do we.

## Errors

`step()` reports `StepError`:

| Error           | Trigger                                   | Effect                    |
|-----------------|-------------------------------------------|---------------------------|
| `None`          | normal execution                          | continue                  |
| `UnknownOpcode` | opcode not in the table above             | `halted ← 1`              |
| `BadRegister`   | register field > 3                        | `halted ← 1`              |

A failed step still consumes its fetch cost (see below), leaves memory and
registers untouched by the aborted instruction, and halts the machine.
Undefined-opcode behavior being deterministic is what makes cross-emulator
trace comparison possible later.

### Cycle costs on error

Fetching an unknown opcode costs 2 cycles (opcode + abort). A bad-register
error costs 4 (operands were fetched before decode rejected them).

## StepResult

```cpp
struct StepResult {
    uint32_t cycles;  // cycles consumed by THIS instruction
    uint16_t pc;      // pc AFTER the step (address of next instruction)
    StepError error;
};
```

Every layer of every emulator in this course hangs off `step()` — unit tests,
the headless runner, tracing, and scheduling all call it.

## Canonical trace format

One line per executed instruction, written BEFORE the instruction's effects:

```
pc=07 op=50 r0=06 r1=01 r2=00 r3=00 cyc=4
```

- `pc` / `op` / `r0..r3`: machine state as the instruction was fetched,
  two uppercase hex digits each.
- `cyc`: cycles consumed by this instruction, decimal (so variable-cost JZ
  shows up directly in the trace).
- Exactly these seven fields, whitespace-separated, lowercase keys — this is
  the format `tools/labs/compare_trace.py` aligns and diffs.

## Disassembly

Every core also exposes `disassemble(addr)` returning text like
`ADD r0, r1` or `.byte #0x99` for undefined opcodes. Disassemblers arrive
early (house rule): they are how you read core dumps and trace logs.
