# Lecture — Accuracy, Quirks and Debugging

> Study emulator compatibility: instruction traces, breakpoints, step,
> register dumps, memory watch, quirks, golden screenshots.

## 1. The screen lies

When a game glitches, the wrong pixel is almost never where the bug is. A
sprite is one frame late because a register was set two instructions early
because a carry flag was computed wrong — three layers away from the
symptom. Professional emulator work therefore starts at the CPU:

```text
known-good emulator ── trace A ─┐
                                ├─ compare → FIRST divergence
your emulator      ── trace B ─┘
```

You compare pc, opcode, registers, flags, memory accesses, cycles — and you
fix the first line that disagrees, not the last thing that looks broken.
From the 8080 phase onward this workflow is mandatory; here it becomes
muscle memory on a machine small enough to see all of it.

## 2. What a trace must contain

One line per executed instruction, whitespace-separated `key=value`:

```text
pc=0200 op=00E0 V0=00 I=000 SP=0F cyc=11
```

Canonical mode carries enough to locate an instruction in time. Full mode
dumps *everything* — every V register, I, SP, DT, ST — because quirk bugs
hide in exactly the registers a canonical trace omits. Traces must be
byte-reproducible: no wall clock, no host randomness (our CXKK uses a
fixed-seed LCG), timers tick deterministically once per frame of 11
instructions.

## 3. The debugger commands

```text
step [n]            execute n instructions, printing a trace line each
continue            run until a breakpoint/watchpoint or program end
regs                register dump
memory <addr> [len] hex dump of RAM
break <addr>        stop BEFORE the instruction at addr executes
disasm [n]          disassemble ahead of PC — every CPU needs one (§55)
watch 400:4         break when any byte in a range changes
watch V3==2A        break when a register predicate turns true
quit
```

Breakpoints and stepping exist for humans; scripts drive the same REPL via
`--script`, which is why every session output in this chapter can be diffed
in CI. Stepping is also a core API (`StepResult step()`), not just a
debugger feature — testing, tracing and scheduling all sit on it (§56).

## 4. Golden traces and golden screenshots

A "golden" is reference output generated by an implementation you trust:
run it twice, require identical bytes, commit it next to its generating
command (see `tests/public/ch06_chip8_accuracy_debugger/provenance.md`).
Framebuffers hash to a digest (`--hash-frame`); traces compare with
`tools/labs/compare_trace.py`, which reports the first diverging line with
context. Never hand-invent a hash — if your fix changes goldens, regenerate
and document them.

## 5. Quirks: compatibility as configuration

CHIP-8's afterlife produced a family tree rather than a standard. Most
software targeted the COSMAC VIP; CHIP-48 modernized some opcodes and
*bugged* others (the BXNN jump indexes VX instead of V0); today's
interpreters standardized different choices again. Consequences:

- `8XY6`: original shifts VY into VX; modern shifts VX.
- `FX55`/`FX65`: original leaves I alone; CHIP-48 onward advances I by X+1.
- `DXYN`: sprites wrap around edges on the VIP, clip elsewhere.
- VF handling differs around FX1E/FX55/FX65.

The engineering answer is `struct Chip8Quirks` — five booleans, three named
presets, selected at runtime like any other configuration. Emulators that
hardcode one variant are wrong for most of the ROM library; emulators with
profiles are right for all of it. Our differential fixtures pin each flag
by making two profiles produce observably different final state.
