# 91 — Challenge: Boot an NROM ROM Headlessly

The acceptance bar for a bus + cartridge stack is blunt: put a real iNES
image on the cable, hit reset, and prove the game's own code ran.

## The fixture

`tests/public/ch20_nes_bus_cartridges/roms/boot_success.nes` is a
course-original NROM image (16KB PRG, 8KB CHR, horizontal mirroring,
generated by `02_ines_nrom/tools/gen_fixtures.py`). Its init block does
exactly what homebrew startup code does:

```text
SEI CLD LDX #$FF TXS      ; standard init dance
LDA #$77 ; STA $02        <- the success code, written by GAME code
LDA #$55 ; STA $03        <- witness cell
loop: INC $04 ; JMP loop  <- heartbeat so you can tell it's alive
```

## Your task

1. Finish the boot-subset dispatcher in `nesboot.hpp` (`step()`).
2. Boot the ROM and assert through the bus — not through the CPU:

   ```bash
   ./ch20_91_boot_runner \
       --rom tests/public/ch20_nes_bus_cartridges/roms/boot_success.nes \
       --headless --cycles 500 \
       --dump-ram /tmp/ram.bin --expect-ram 02=77 --expect-ram 03=55
   echo $?    # must be 0
   ```

3. The automated test embeds the same image and checks `$02 == $77`,
   `$03 == $55` and that the heartbeat counter at `$04` keeps incrementing.

## Acceptance

- Both tests green; runner exits 0 with both `--expect-ram` cells.
- `vertical.nes` parses with vertical mirroring; `chrram.nes` reports zero
  CHR banks (that variant is the coding test).
