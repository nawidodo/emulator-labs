# CHALLENGE — 91_challenge: render a supplied scene state

Real emulator testing eventually means "load a captured machine state and
compare pixels". Here the state is a `.sns` scene container: magic
`SNESSCN1`, a 64-byte register block (mode, BG bases and scrolls, the Mode
7 matrix, window and color-math flags), then VRAM, CGRAM and OAM images —
68304 bytes total. The exact layout is in `scene.hpp`.

## Your task

1. Read `scene.hpp` until you can predict what each scene renders without
   running it: which layers exist, where the window sits, whether math is
   add or subtract, how the Mode 7 matrix zooms/rotates.
2. Run the runner on both committed scenes:

```bash
./ch32_91_scene_runner --rom fixtures/baseline.sns --headless \
    --frames 1 --hash-frame /tmp/baseline.rgba
./ch32_91_scene_runner --rom fixtures/mode7_zoom.sns --headless \
    --frames 1 --hash-frame /tmp/mode7.rgba
```

3. Verify acceptance criteria below.
4. (Recommended) Mutate one register byte in a copy of a scene — e.g.
   flip the window invert bit at offset `0x3E` — predict which region of
   the frame changes BEFORE re-running, then confirm. That prediction is
   the actual skill being tested.

## Acceptance criteria

| # | criterion | check |
|---|-----------|-------|
| 1 | baseline frame matches the reference renderer | FNV-1a-64 of the RGBA dump = `8BD7BF88470974A5` |
| 2 | mode 7 scene matches | FNV-1a-64 = `2564D946AB36EC88` |
| 3 | rendering is deterministic | two runs are byte-identical (`cmp`) |
| 4 | CLI contract | `--help` exits 0; unknown flags exit nonzero |

Hash tool: `python3 tools/labs/hash_frame.py FILE` (FNV64 line).

The hidden grading bundle contains a third scene rendered with the same
runner; its digest lives in `tests/hidden/ch32_snes_bus_ppu/manifest.json`.

## Provenance

Both fixtures were generated by `fixtures/make_scenes.py`
(deterministic, no RNG). Golden hashes were produced by the reference
solution, run twice per scene with byte-identical output. See
`tests/public/ch32_snes_bus_ppu/provenance.md`.
