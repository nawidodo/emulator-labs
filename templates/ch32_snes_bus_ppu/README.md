# Chapter 32 — SNES Bus and PPU

Build the SNES display system from the address decoder up to a full Mode 7
affine renderer: banked memory decoding, VRAM/CGRAM/OAM, background modes
0 and 1 with windows and color math, then the fixed-point warp of Mode 7.

## Conventions

* **Runner CLI** — every runner accepts the chapter-standard flag set:
  `--rom PATH --headless --cycles N --frames N --trace FILE
  --hash-frame FILE --input-file FILE`. Documented deviations:
  * There is no CPU in this chapter, so `--cycles` is accepted as a
    no-op and `--trace` writes nothing (no `pc=/op=/cyc=` trace exists).
  * For `01..03` runners `--rom`/`--input-file` are accepted no-ops:
    their scenes are built into the binary. Only `91_challenge`'s runner
    *requires* `--rom` (the `.sns` scene container).
  * `--hash-frame FILE` writes the raw hashable artifact: a 256x224x4
    RGBA byte dump (row-major, R,G,B,A per pixel). Graders FNV-1a-64
    these bytes.
* **`.sns` scene container** (91_challenge): `"SNESSCN1"` magic, version,
  64-byte register block (mode 0/1/7, BG bases + scrolls, Mode 7 matrix,
  window, color math), then VRAM (64 KiB), CGRAM (512 B), OAM low
  (2048 B) and OAM high (128 B). Total 68304 bytes. Exact layout:
  `91_challenge/scene.hpp`.
* **Palette bands / composition rule / window semantics** — documented
  exactly in `03_bg_render/render.hpp`; the coding test's mini format is
  documented in `99_coding_test/coding.hpp` and `SPEC.md`.
* **Fixtures** — all synthetic; no commercial ROMs. Scene bundles are
  generated by `91_challenge/fixtures/make_scenes.py` with provenance
  next to the goldens.
