# 90_debug fixture provenance

## fixtures/gradient_table.bin

224 bytes: the per-line INIDISP ($2100) brightness table used by the debug
exercise. Byte n is the brightness applied at the START of scanline n.
Values are `min(15, n*16/224)` — a monotonic ramp that saturates at
brightness 15 for the last quarter of the frame. Hand-generated (pure
arithmetic, no hardware or emulator involved); synthetic data only, no
commercial ROM content.

## golden/gradient_writes.log

Golden HDMA write log of the CORRECTED engine:

```
line=<n> val=<hex brightness>
```

one line per scanline, 224 lines total. Generated by running the reference
solution of `90_debug/hdma_line.hpp` over `fixtures/gradient_table.bin`:

```
# generator (reference implementation, run twice -- byte-identical):
#   GradientHdma hdma; hdma.load_table(gradient_table.bin); hdma.run();
#   emit "line=%d val=%02x" per LineWrite
```

The identical values are embedded in `main.cpp` (`ramp()`), so the tests do
not depend on file paths at runtime; this log is the human-readable record
of what the corrected engine must produce. First observable divergence of
the seeded bug vs this golden: **line 0** (bug emits nothing) and **line 1**
(bug emits `val=00`, the stale previous-line value).
