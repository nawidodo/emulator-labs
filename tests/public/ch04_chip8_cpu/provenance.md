# provenance.md — ch04_chip8_cpu golden data

All goldens in this tree were generated by the ch04 reference solution
(generated via `python3 tools/labs/generate.py --mode solution --targets
ch04_chip8_cpu`, then built). Every file below was produced TWICE by the
commands listed; both runs were byte-identical (verified with `cmp`) before
committing. Never hand-edit a golden — regenerate instead.

## Generating commands

`RUNNER` is the solution-tree runner for the given exercise, `ROMS` is
`tests/public/ch04_chip8_cpu/roms`, `IN` is `.../input`, and each command was
run twice with byte-identical output:

```
# traces/control_flow.golden.log + regs/control_flow.json
$RUNNER_01 --rom $ROMS/control_flow.bin --headless --cycles 300 \
    --trace <out>.log --regs <out>.json

# traces/alu.golden.log + regs/alu.json
$RUNNER_02 --rom $ROMS/alu.bin --headless --cycles 300 ...

# traces/shift_quirks_{cosmac,modern}.golden.log (+ regs)
$RUNNER_03 --rom $ROMS/shift_quirks.bin ... [--quirks modern]

# traces/memory_bcd.golden.log + regs
$RUNNER_04 --rom $ROMS/memory_bcd.bin ...

# traces/random_key.golden.log + regs (scripted keys, default LCG seed)
$RUNNER_05 --rom $ROMS/random_key.bin ... --input-file $IN/random_key.input

# traces/flags_suite{,_modern}.golden.log + regs
$RUNNER_06 --rom $ROMS/flags_suite.bin ... [--quirks modern]
```

A second full pass into a fresh directory reproduced every trace and regs
file byte-identically (`cmp`). The flags suite additionally produces the SAME
register state under both quirk profiles (only I differs before the suite's
explicit `LD I,#10F` normalization; after it nothing differs).

## Fixture ROMs

Every `.bin` under `roms/` is hand-assembled by the chapter author from the
adjacent `.asm.txt` listing (the listing is the canonical source; the binary
was assembled from it). No commercial ROM content. The RNG in fixtures uses
the machine's fixed default seed (0x5EEDC0488) plus an explicit LCG defined
in chip8.hpp; first bytes for seed 1 are 6C 82 A5 62 CB 80.
